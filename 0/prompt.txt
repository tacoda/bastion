  ### 2. Discovery and registration
  The provider declares itself, and the router also finds live providers by function name.
  - **Provider declares itself.** The provider calls **`router::provider::register`** at boot and retries with backoff (500 ms, doubling, max 10 s) until it gets an ack. [B register.rs, README]
    - Payload (`ProviderDeclaration`): `{id (required), display_name?, credential_env_var?, credential_optional?, defaults?: {api_url?, max_tokens?, …extra}, config_schema?, supports_model_listing?, default_models?, default_thinking_level?, context_overflow_hint?, models?, worker_id?, icon_svg?, token?}`.
    - Response: `{id, ok, registration_token}`.
    - The provider stores the raw token in `state::set {scope: "<worker-name>", key: "registration_token"}` and sends it as `token` on every later register, resolve, or reconcile call. The router keeps only a sha256 of it. Re-registering an id without the original token is rejected as an anti-takeover guard. [B state.rs, README]
    - Id rule: `[a-z0-9_-]{1,64}`, so no `::`. [B registry/register.rs:24]
  - **Re-declare on restart.** The provider calls `register_trigger("router::ready", "provider::<id>::on_router_ready", {})`. [B]
  - **Router finds providers by name.** The router also calls `engine::functions::list {prefix:"provider::", include_internal:true}`. It treats each `provider::<id>::on_router_ready` as a live provider and nudges it to re-declare after function registrations change. So registering that function is effectively required. [B registry/rediscover.rs]
  - **Dispatch.** The router calls `format!("provider::{id}::stream")`. [C] router string `provider::` / `::stream`
  - **Model routing.** The router routes `{model, provider?}` with `router::chat` in this order [B routing.rs]:
    1. An explicit provider.
    2. The unique available catalog owner of the model id. Two or more owners is an "ambiguous" error.
    3. `routing_heuristics`.
    4. `default_provider`.
  
    Because of rule 2, each host's catalog model ids must be distinct. openrouter prefixes its ids with `openrouter/`.
  - **Config entry.** It is a single engine configuration entry with id `llm-router`. The router composes its schema from the declarations. [B README]
    ```json
    {"default_provider":"…","providers":{"<id>":{"api_key":"secret://NAME","api_url":"https://…/chat/completions","max_tokens":8192}},
     "routing_heuristics":[{"pattern":"^gpt-","provider":"openai"}],"settings":{"stream_timeout_ms":600000,"idle_timeout_ms":120000,"retry_max":2,"output_token_max":null}}
    ```
    The default slice schema is `{api_key (writeOnly), api_url, max_tokens}` when `config_schema` is null. A custom `config_schema` must mark any secret-looking field `writeOnly: true`. [B config/schema.rs]
  - **Catalog writes.** `router::models::reconcile {provider, models: Model[], token, discovery?}` returns `{provider, count}`. It is the only catalog write path. [A]
  
  ### 3. Streaming
  - The router creates an engine channel and passes the writer half as `writer_ref`. The provider opens it with **`iii_sdk::channel::ChannelWriter::new(iii.address(), &writer_ref)`**. Each frame is one JSON text message sent with `writer.send_message(&json).await`. The provider calls `writer.close().await` at the end. That API exists in iii-sdk 0.25.0 [D channels.rs:130-185]. llm-router's `open_sink` uses exactly this [B src/channels.rs].
  - **Frames.** Each frame is `AssistantMessageEvent`, tagged on `type` (snake_case), and the vocabulary is frozen [B types/events.rs]:
    - `start {partial}`
    - `text_start {partial}`, `text_delta {delta}`, `text_end {partial}`
    - `thinking_start`, `thinking_delta`, `thinking_end` (same shapes as the text frames)
    - `functioncall_start {partial}`, `functioncall_delta {delta, id}`, `functioncall_end {partial}`
    - `usage {usage:{input,output,cache_read,cache_write,reasoning,cost_usd}}`
    - `ping`
    - `stop {stop_reason, error_message?, error_kind?}`
    - Terminal, exactly one and last: `done {message: AssistantMessage}` or `error {error: AssistantMessage}`.
  - `partial` and `message` are full `AssistantMessage` snapshots with `provider` set to the provider id. Delta frames carry only `delta`.
  - `stop_reason` is one of `end|length|function_call|aborted|error`. `error_kind` is one of `auth_expired|rate_limited|context_overflow|transient|permanent`. The router retries only `rate_limited` and `transient`, and only before the first frame is forwarded. Providers must not retry themselves. [B events.rs, README]
  - Send a `ping` at least every 30 s of upstream silence. The router's idle timeout is 120 s by default. [B stream_fn.rs]
  - Treat a closed channel as cancellation, and abort the upstream request. [B README]
  - **Tool calls.**
    - Outbound: `tools[]` maps to Chat Completions `{"type":"function","function":{name, description, parameters}}`, with names encoded as `::` → `__` (e.g. `agent::trigger` → `agent__trigger`).
    - Inbound: upstream `tool_calls` come back as `function_call {id, function_id: <decoded name>, arguments: <parsed JSON>}` blocks, with `stop_reason: function_call`.
    - History: `function_result` messages map to role `tool` messages. [B wire/tools.rs, wire/messages.rs, provider_scaffold/names.rs]
  
  ### 4. Secrets
  **The router resolves the secret and passes the key.** The provider never calls `secrets::*`.
  - Per request, the provider calls `router::provider::resolve {id, token, begin_discovery?}`. [A][B router_client.rs]
  - Response: `{configured, source: config|env|none, credential?: {type:"api_key", key} | {type:"oauth", access_token, …}, api_url?, max_tokens?, credential_source?: config|env|secret|none, credential_ref?, credential_error?, discovery_attempt?}`.
  - `api_url` and `max_tokens` come from the slice, else from the declaration's `defaults`.
  - The secret's `consumers` must include `llm-router`, not your worker.
  - If you get `credential_source: "secret"` with no credential, report `credential_error`. Do not fall back to an env var. [B README "Credentials", "Operational notes"]
  
  ### Implications for your worker
  - **You cannot reuse the `llm-router` crate.** No llm-router release pins iii-sdk 0.25.0. Tags v1.4.41 and v1.4.42 pin `iii-sdk = "=0.24.6"`, v1.5.x pins `=0.26.0-rc.5`, and the crate is a path dependency inside the monorepo, not on crates.io. The comment in openrouter's Cargo.toml says the provider and router must share one `IIIClient` type. So with iii-sdk 0.25.0 you must hand-write serde types for the JSON above. The wire is version-independent: 0.24.6-built providers run against this 0.25 engine today (kimi, openrouter) [A].
  - **One worker can serve several hosts.** For each configured host, register `provider::<host_id>::{stream,refresh_models,on_router_ready,abort}`, call `register` with that id, store one token per id (for example `state` key `registration_token:<id>`), and bind `router::ready` once per handler.
  - **Point `api_url` at the full URL.** openrouter and deepseek POST directly to `api_url`, which is the full `/chat/completions` URL (deepseek's binary has `https://api.deepseek.com/chat/completions`). The `/models` URL is derived separately.
