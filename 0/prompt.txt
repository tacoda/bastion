  ### Top 10 gaps by value
  1. **Machine-verdict gate on promote-class calls (opengantry).** Bastion pins the worker but nothing calls it. Today a dark merge or land rests on the dial alone.
  2. **Predicates beyond ordered-word matching.** Bastion needs file and diff predicates (secrets, for example) that run in-turn and at review from one implementation.
  3. **Workspace prepare, cleanup and env, per-workspace concurrency, branch prefix and revision budget.** These are needed for real stacks, and A9 has them pending.
  4. **Improve/Learn to Proposals with evidence tracing.** This includes ghola's never_fired vs unobservable signal and the rule that accept only writes a spec or a ladder move (A10).
  5. **Deterministic eval graders and case files**, including contract, verdict-is, mentions and cites-evidence. Bastion's judge turn is too coarse: every run graded 7.
  6. **Evidence-required PROVEN downgrade and configurable output contracts.**
  7. **Publishing gate** over the PR title and body: no AI attribution, no secrets.
  8. **Cost truthfulness**: an unknown cost is not $0, plus pricing fallback, a per-stage cap and the A9 Costs page.
  9. **Org and team rule packs (shared layers).** Bastion constraints are per-server DB rows, so a team cannot share one pack across servers or repos.

  ### Conflicts with Bastion's design
  - **Ghola rejects an HTTP surface; Bastion is built on one.** Ghola says it has no HTTP surface and no dashboard, and treats the console as the UI. Bastion is an axum HTTP and SSE server with a native client (D27–D29). Ghola's arrakis comment also warns against a write-capable unauthenticated port. Bastion answers that with tokens and roles (D31, D32).
  - **Merging.** Ghola's rule is that nothing merges itself and Bastion never merges. Bastion merges on a person's approve, and a dark dial can run to a merged change (O exit). This is compatible with "a person decides" only if the dial cannot reach merge unattended. Bastion's O exit runs dark all the way to merge, which ghola forbids.
  - **Configuration home.** Ghola keeps config as files in git, with `settings/*.yaml`, `make config` and "no upgrade path". Bastion keeps settings in the database with versions (D26). File-in-git review and the git-tracked charter of rules differ.
  - **Single operator vs multi-user.** Ghola is single-operator by stated non-goal. Bastion has people and roles. Memory says multi-user and hosting are open, so this is not a blocker.
  - **Ladder model.** Ghola's rungs are mechanisms (0–5, incl. CI, out of reach). Bastion's are strengths (told, checked, enforced). Porting "carry at a second rung" or "CI rung" needs a decision, not a copy.
  - **Extension model.** Ghola uses Python files found by filename, or any function id on the bus. D1 says all Bastion code is Rust and D7 says stock workers come first. Bastion workflow nodes are skill, prompt or command, so arbitrary code-defined guards and actions conflict with D1 unless they are workers.
  - **Swappable upstream workers.** Ghola's ladder and audit are separate bus workers (`ladder::*`, `audit::*`) you can swap. Bastion puts the gate and audit inside `bastion-core` and `bastion-server` (D18, D21), so a "swap the provider" seam does not exist by design.
  - **State store.** Ghola uses JSON files, while Bastion uses `database` rows with a `rev`. Both reject the volatile `state` worker, so they agree on that.

The module doc says "Without an audit writer it refuses every call", but that only holds when there is no key, not when writes fail.
  - Fix:
    - Keep the head record and retry it with backoff instead of dropping it. Clear `last_error` on success.
    - Spool queued records to `data/audit-spool.jsonl` so they survive a server restart.
    - For stack stop, write the record and await it before running `iii kill`.

As the chain grows, every append times out, so all audit writes fail silently. The unbounded `mpsc` queue also grows without limit, because records arrive faster than one per 5 s. `GET /audit` and the export load the whole chain with no paging.

    - Use a bounded channel.
